# 证据可追溯性与过程透明度改造产品方向文档

> 文档类型：产品方向文档（含设计原则、功能描述、优先级）
> 适用阶段：产品对齐与设计评审
> 关联背景：基于当前 Agentic RAG 聊天结果页的体验诊断与业界最佳实践调研

---

## 1. 背景与问题诊断

### 1.1 核心体验问题

当前系统在两个维度上存在根本性的体验缺陷：

**问题一：引用是"工具调用日志"，不是"证据"**

用户看到的"关键证据"展示的仍更接近"本次回答读取了 `read_note_file`、`grep`、`glob` 等工具结果"，而不是"**这句具体的话**来自**你的这段笔记**"。这意味着：

- 用户无法验证具体断言是否有依据
- 引用与回答正文之间没有可感知的对应关系
- 用户只能相信整体答案，无法局部核查

**问题二：过程透明度是"操作日志"，不是"推理摘要"**

当前过程区展示的是工具名称 + 完成状态（✓），调试抽屉展示的是原始 JSON。两者都缺少最关键的东西：**agent 在找什么、找到了什么、为什么这样做**。用户看到 `grep ✓` 或 `glob ✓` 时，不一定知道 agent 搜索了什么关键词、定位了哪些候选文件；看到 `read_note_file ✓` 时，也不一定知道读了哪个文件的哪个部分。

### 1.2 信息架构的定位偏差

当前 AnswerPanel 的五段式结构（结论 → 行动 → 风险/置信度 → 证据 → 正文）是为"决策型 AI 助手"设计的。但 Second Brain 的核心使用场景是**个人知识库查询与学习复盘**，两种场景对信息架构的需求有本质差异：

| 维度 | 决策型 AI 助手 | 个人知识库（Second Brain） |
|---|---|---|
| 用户对信息的态度 | 不确定信息是否可信，需要"相信" | 知道自己写过什么，需要"想起" |
| 引用的核心价值 | 证明答案的权威性 | 帮用户快速回到当时记录的上下文 |
| 置信度的意义 | 帮助用户决策是否采纳 | 通常没有意义（用户自己的笔记） |
| 过程的意义 | 监控 AI 是否在做正确的事 | 理解 AI 是否找到了正确的笔记 |

这一偏差导致当前 UI 给用户展示了大量对他们没有价值的信息（置信度卡片、风险列表），却缺少最有价值的信息（这句话来自你哪条笔记的哪段话）。

---

## 2. 设计目标

本次改造围绕以下四个目标展开，优先级从高到低：

1. **断言可溯源**：回答中的每个关键事实断言，用户都能一键定位到原始笔记中的对应片段
2. **过程可理解**：过程摘要能让用户理解"agent 找了什么、找到了什么"，而非只知道"做了几步操作"
3. **架构符合场景**：信息呈现顺序和层级符合"个人记忆索引"而非"决策支持系统"的使用意图
4. **诚实优于完整**：当系统无法找到可靠依据时，明确告知用户，而非给出低质量的伪结构化答案

---

## 3. 功能设计

### 3.1 方向 A：精准回溯原文

**这是本次改造中价值最高、优先级最高的方向。**

#### 3.1.1 产品定义

用户在阅读回答时，如果看到某个关键断言带有引用标记，就应该能够：

- 点击该引用，打开对应笔记
- 打开后直接落到对应原文片段附近
- 一眼看出哪段内容在支撑刚才那句话，而不是自己在整篇笔记里翻找

#### 3.1.2 最小必要交互

**正文中的引用标记：**

- 回答中的关键断言旁展示可点击引用标记
- 标记样式做到可识别、可点击

**点击后的结果：**

- 打开笔记预览面板
- 预览面板默认加载引用位置附近内容，而不是总从文件头开始
- 对应片段需要有明确的视觉提示，帮助用户快速确认“这就是证据”

**来源列表：**

- 保留底部引用面板
- 每条引用至少展示：编号、文件名、原文片段、跳转入口

#### 3.1.3 验收标准

满足以下条件即可判定“精准回溯原文”达标：

1. 在有直接证据支撑的回答中，核心事实句旁能看到可点击的引用标记
2. 用户点击引用后，能在 2 步内直接看到对应笔记中的支撑片段，而不是从文件开头重新查找
3. 打开后，支撑片段有明确的视觉提示，用户无需自己在整篇笔记中翻找，就能确认“这就是这句话的依据”
4. 该体验应在日常常见的命中类问答中可重复获得，而不是只在少数演示样例中成立

#### 3.1.4 最小实现依赖

实现这一目标至少需要建立"回答中的引用标记 -> 原文片段位置"的映射：

- 优先基于 OpenCode 原生 session / event 主链路，为证据片段分配稳定 ID（如 `[c01]`）
- 模型生成的回答中输出对应引用标记
- 前端根据 `source_refs` 中的路径、偏移量、片段信息完成跳转和定位

---

### 3.2 方向 B：过程语义化摘要

**让用户理解"agent 找了什么、找到了什么"，而非只看到操作状态。**

#### 3.2.1 体验目标

展开过程区后，用户能看到每个步骤的**语义摘要**，而不是工具名 + 状态符号。摘要应该回答：这一步在做什么？输入是什么？结果如何？

#### 3.2.2 步骤摘要设计

每个工具调用展示一行语义化摘要：

```
过程摘要  [已完成，耗时 3.2s]  [展开 ▾]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✓ 搜索文件内容    "零钱兑换 系统性错误"  →  命中 8 条
✓ 定位候选文件    "leetcode*submission*"  →  命中 3 个文件
✓ 读取文件    leetcode_submissions.md（第 1505 行附近）
✓ 执行代码    验证提交记录统计  →  共 23 次提交，12 次 AC
```

格式说明：
- 工具类型用语义标签（如"搜索文件内容"/"定位候选文件"/"读取文件"/"执行代码"），而非工具函数名
- 关键参数（查询词、文件名、代码摘要）直接展示在摘要行
- 结果摘要（命中数量、执行结论）也在同一行展示
- 失败步骤显示失败原因摘要，而非只显示 ✕

#### 3.2.3 过程摘要的层级结构

```
[过程摘要条]  已完成 · 4 个步骤 · 3.2s  [▾ 展开]
  └── [语义化步骤列表]（展开后可见）
        每行一个步骤：图标 + 语义标签 + 关键参数 + 结果摘要
        └── [查看完整调试详情]（保留现有调试抽屉入口）
```

调试抽屉（完整工具参数/结果 JSON）保留现有实现，作为专家层入口。

---

### 3.3 方向 C：AnswerPanel 信息架构重定位

**从"决策型 AI 助手"切换为"个人记忆索引"的信息架构。**

#### 3.3.1 新的信息层级

```
┌─────────────────────────────────────────┐
│  [直接回答]                              │
│  1-3 句话，直接回答用户的问题             │
├─────────────────────────────────────────┤
│  [来自你的笔记]                          │
│  ¹ algo_notes.md · 2024-06              │
│    "背包问题的状态转移方程为..."  [→]    │
│  ² leetcode_submissions.md · 2024-09    │
│    "WA: 第 322 题，边界条件..."  [→]    │
├─────────────────────────────────────────┤
│  [完整分析]  ▾ 展开                      │
│  （完整 Markdown 正文，默认折叠）         │
└─────────────────────────────────────────┘
```

核心变化：
- **直接回答前置**：首屏第一眼看到的是对问题的直接回答，而非置信度卡片或结论标签
- **引用紧跟回答**：引用不是附录，而是回答的组成部分，紧接在直接回答之后
- **完整正文折叠**：详细分析内容默认折叠，用户主动展开；简单查询不需要看长篇正文
- **移除置信度卡片**：`confidence: high/medium/low` 是规则生成的，对用户没有实际意义，移除
- **移除行动清单和风险列表**：这些字段对个人知识库查询场景不适用，在无法稳定产出时不展示

#### 3.3.2 降级处理

当结构化字段不可用时（无 `decisionSummary` 或 `evidence`）：

```
┌─────────────────────────────────────────┐
│  [完整回答]                              │
│  （Markdown 正文直接展示）               │
│                                         │
│  [来自你的笔记]（如有 source_refs）      │
│  · algo_notes.md  [→]                  │
└─────────────────────────────────────────┘
```

即使没有 inline citation，只要有 `source_refs`，就展示文件级引用面板。这是当前已有能力，应作为兜底而非异常状态。

### 3.4 方向 D：诚实性信号

**让用户能判断回答的可靠程度，系统应该主动说明局限性。**

#### 3.4.1 无结果时的诚实提示

当本次回答没有可靠证据命中时（如没有 `source_refs`、没有有效文件命中，或仅命中弱相关内容），回答中应包含明确说明：

```
⚠ 你的笔记中没有关于 [X] 的直接记录。
以下分析基于相关笔记推断，可信度有限：

[推断内容...]
```

这需要主链路在工具调用结果或事件元数据中暴露证据质量信号（如 `source_refs` 为空、仅有文件级命中、弱相关分数标记），并在系统提示中要求模型主动声明。

#### 3.4.2 推断性内容的标注

当回答中包含无法溯源到具体笔记的推断性内容时，模型应在该段落前加标注（通过系统提示约束）：

```
[基于笔记推断]
由于你的笔记中没有直接记录，以下是基于现有内容的推断...
```

#### 3.4.3 移除虚假精确感的元素

以下元素因为是规则生成而非真实语义，应从默认视图中移除：
- `confidence: high/medium/low/unknown` 置信度卡片
- `assumptions` 关键假设列表（通常是空列表或无意义内容）
- `risks` 风险列表（对个人笔记查询场景不适用）

如需保留这些字段用于特殊场景（如未来的决策支持功能），可放入可选的"详细分析"折叠区，不作为默认展示内容。

## 4. 优先级与实施路径

### 4.1 优先级矩阵

| 方向 | 用户价值 | 实施复杂度 | 优先级 |
|---|---|---|---|
| A：精准回溯原文 | 极高 | 高（需主链路引用语义改造） | P0 |
| C：AnswerPanel 重定位 | 高 | 中（前端重构） | P0 |
| D：诚实性信号 | 高 | 中（主链路信号 + 前端标注） | P1 |
| B：过程语义化摘要 | 中 | 中（前端格式化逻辑） | P1 |

### 4.2 建议实施顺序

**P0：建立正确的信息架构基础**

1. 重构 AnswerPanel 信息层级（方向 C）
   - 移除置信度卡片、行动清单、风险列表
   - 实现"直接回答 + 引用 + 折叠正文"三段式布局
   - 确保降级路径（无结构化字段时）仍能展示文件级引用

2. OpenCode 主链路改造，支持 chunk / 片段 ID 引用（方向 A 的链路部分）
   - 证据片段分配稳定 ID
   - session / event 元数据提供 `source_refs`
   - 系统提示增加耦合引用指令

**P0：实现精准回溯原文**

3. 前端 inline citation 解析与渲染（方向 A 的前端部分）
   - 解析回答中的 `[c01]` 标记
   - 实现可点击引用标记
   - 点击后打开对应笔记并定位到对应片段
   - 实现底部 References Panel

**P1：完善透明度与诚实性**

4. 诚实性信号（方向 D）
   - 主链路暴露弱证据 / 无证据标记
   - 系统提示约束：无结果时主动声明
   - 前端：推断性内容标注

5. 过程语义化摘要（方向 B）
   - ProcessGroupList 步骤摘要格式化
   - 工具参数关键字段提取与展示

---

## 5. 非目标

以下内容**不在本次改造范围内**：

- 移动端专项适配
- `decisionSummary` 的 LLM 结构化抽取（当前规则降级已足够，且信息架构重定位后该字段价值降低）
- `semantic` 中间事件的实时推送（复杂度高，收益有限）
- 多用户权限感知引用（个人系统不适用）

---

## 6. 成功指标

**定性验收（用户体验层面）：**
- 用户能在不打开调试抽屉的情况下，理解"这个回答基于我的哪些笔记"
- 用户能通过点击引用角标，在 2 步操作内看到原笔记中的支撑片段，并立即知道它为什么支撑当前回答
- 当系统没有找到相关笔记时，用户能清楚感知到这一点，而非收到一个没有引用的答案

---

## 7. 设计原则总结

本次改造的核心设计哲学，来自对业界最佳实践的提炼：

> **引用不是装饰，是阅读路径的一部分。**
> 最好的引用体验是：用户在读到某个说法时，能就地（inline）看到它来自哪里，而不需要离开当前阅读位置去查找来源列表。

> **诚实优于完整。**
> 宁可说"你的笔记里没有这方面的记录"，也不给出一个没有引用依据的答案。用户对系统的长期信任，建立在系统偶尔说"我不知道"的能力上。

> **个人知识库的引用是帮你"想起"，不是帮你"相信"。**
> 用户知道自己写过什么，引用的价值不是证明权威性，而是帮他们快速回到当时记录知识时的上下文。时间信息、原文片段、一键跳转，比置信度分数更有价值。
