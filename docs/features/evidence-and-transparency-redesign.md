# 精准回溯原文产品判断

> 当前范围：只讨论“精准回溯原文”
> 关联执行：`docs/features/evidence-and-transparency-rd-plan.md`
> 关联契约：`docs/features/evidence-and-transparency-source-refs-contract.md`

---

## 1. 当前判断

这个需求已经跨过了“有没有精准溯源能力”的阶段，进入了“精准溯源是否真的省力可用”的阶段。

从技术链路看，native 主路径已经成立：

- 回答里的关键断言能带 `[cxx]`
- `source_refs` 已能稳定提供 `path + citation_id + snippet + char_offset`
- 命中类问题已经不再主要依赖 synthetic / file fallback

所以现在的主问题不再是“能不能跳”，而是：

**用户点开 citation 后，能不能在极短时间内确认这就是支撑刚才那句话的原文。**

---

## 2. 用公理看，下一步最该做什么

### T01：基础设施优于组件

当前瓶颈已经不在 citation 渲染，也不在来源面板，而在“证据片段质量”这层基础设施。  
如果 `snippet` 本身带包装噪音、落点偏宽、确认感弱，那么前端再怎么加组件，也只是把问题包起来。

### T02：结果确定性优于过程确定性

下一步不该继续堆 prompt 规则或操作细则，而应该先把成功标准写清楚：

**点开 citation 后，用户应能在 2 秒内确认这就是依据。**

只要这个结果没有稳定成立，就说明这个需求还没真正完成。

### V02：可验证性是信任的地基

“精准回溯原文”本质上不是一个 UI 需求，而是一个可验证性需求。  
如果用户还需要自己在片段里二次搜索，那么系统只是“提供了相关材料”，还没有提供“可验证断言”。

### A12：AI 原生开发范式

下一步优先级应该放在原生证据质量上，而不是应用层补偿。  
要先让 `source_refs.snippet` 更像原文证据，再谈额外 UI 优化。

---

## 3. 结论：下一阶段唯一最该做的事

**把 citation 打开后的证据片段，打磨成“可秒级确认”的产品体验。**

具体来说，就是只盯这一件事：

> 用户点开 `[cxx]` 后，不需要自己再翻找，就能立刻看懂“这段原文为什么支撑刚才那句话”。

这比继续扩展更多透明度功能更重要，也比继续讨论信息架构更重要。  
因为从用户价值上说，这一步是“精准回溯原文”从可用走向可信的最后一道坎。

---

## 4. 这件事具体意味着什么

当前阶段最值得投入的，不是更多功能，而是三条收口要求：

1. `snippet` 更干净  
   片段默认应尽量接近原始笔记内容，去掉 `Assistant`、heading、读取包装等噪音。

2. 落点更聚焦  
   点击后默认看到的应该是支撑当前断言的那一小段，而不是一个“附近差不多在这”的宽泛区域。

3. 确认更省力  
   用户不应再自己读一大段上下文后才明白证据是什么。证据和断言的对应关系应更直接。

---

## 5. 当前完成度

从产品角度看，当前完成度大约是 `80%-85%`。

这说明两件事：

- 这项能力已经具备交付价值
- 但还没有完成最后的产品化收口

当前已经完成的是“能顺着回答回到原文”。  
当前还没完全完成的是“回到原文后能立即确认这就是依据”。

---

## 6. 下一阶段验收标准

下一阶段只看这 4 条：

1. A01、A03、A04、A05 这类命中题中，正文 citation 继续稳定走 `precise/native`
2. 点击 citation 后，默认看到的 `snippet` 不包含明显的系统包装噪音
3. 用户能在 2 秒内判断“这就是支撑刚才那句话的证据”
4. 为了做到上面 3 条，没有把主链路重新退回前端 fallback 或 synthetic 补偿

如果这 4 条稳定成立，就可以认为“精准回溯原文”这个需求基本收口。

---

## 7. 当前阶段不做什么

当前先不扩展这些方向：

- 过程语义化摘要
- 更大的 AnswerPanel 重构
- 更多新的透明度组件
- 为个别题目单独打补丁的过拟合优化

这些都不是当前瓶颈。

---

## 8. 一句话总结

“精准回溯原文”接下来最重要的，不是再证明系统能跳到原文，而是把跳过去之后的那一小段证据，做成真正一眼可确认的产品体验。
