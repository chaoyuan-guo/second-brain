# 溯源效果优化产品定义

> feature 编号：`F02`
> 当前范围：精准溯源效果优化
> 上一阶段成果：`docs/features/01_precise_traceability/`

---

## 1. 产品目标

本阶段不再讨论“能不能生成 native citation”，只优化一个结果：

**用户点击 citation 后，能否在首屏快速确认这就是支撑刚才回答的证据。**

这意味着用户打开后应能快速判断：

- 这段原文是什么
- 它为什么支撑刚才那句话
- 是否还需要继续展开看更多上下文

---

## 2. 产品标准

本阶段达标，不要求“任何复杂文本结构下都命中唯一那条证据”，只要求：

1. 命中类问题继续稳定走 `precise/native`
2. citation 首屏不出现明显系统包装噪音
3. 用户无需二次关键词搜索，即可快速确认证据所在
4. 为了做到以上 3 条，没有把主链路退回前端 fallback 或 synthetic 补偿

产品上真正要解决的是“低认知成本确认”，不是“极端场景下的绝对单条精确命中”。

---

## 3. 本阶段判断

当前这轮优化已经完成本阶段主要目标。

判断依据：

- citation 首屏不再频繁落到 `Assistant`、`User`、XML 包装、工具说明语等系统噪音
- 证据片段与实际依据的距离明显收窄
- 用户大多数情况下已经可以在首屏快速确认“这就是支撑回答的证据”

样本层面的阶段结论：

- A01：达标
- A03：达标
- A04：达标
- A05：显著改善，但仍存在密集相邻提交场景下的边角问题

因此，本阶段可以按“已交付”收口。

---

## 4. 不继续深挖的原因

当前剩余问题主要出现在：

- 同一题下多次相邻错误提交
- 内容结构高度相似
- 用户又希望稳定命中其中某一条或某两条

从产品视角看，这已经不是本阶段的主问题。

继续为此追加更复杂规则，风险大于收益：

- 会明显增加实现复杂度
- 会提高误伤其他正常场景的风险
- 更容易滑向样本过拟合，而不是真实用户价值

因此，本阶段的产品决策是：

**在当前体验水平收口，不为了少数极端密集样本继续复杂化。**

后续是否重开这一问题，只由真实用户反馈决定。

---

## 5. 验收口径

本阶段产品验收按以下口径执行：

1. 命中类问题里，正文 citation 继续稳定走 `precise/native`
2. 点击 citation 后，默认证据片段不包含明显系统包装噪音：
   - `Assistant`
   - `User`
   - XML/标签式包装
   - 工具说明语
   - 与当前断言无关的读取元信息
3. 首屏可见区域应覆盖 citation 对应的核心证据片段
4. 用户不应再需要先做二次关键词搜索，或阅读大段无关上下文后，才能确认依据位置
5. 不允许为了改善体验，把主链路改回前端补偿、回答正文反推 citation，或以 synthetic/source path 冒充 native precise

补充说明：

- A05 这类密集相邻提交场景，当前要求是“能快速确认正确题目与相关证据区域”
- 不要求在本阶段稳定命中其中唯一一条相邻提交

---

## 6. 非目标

- 不重开主链路改造
- 不把前端 fallback 升级为默认主链路
- 不为个别样本做持续叠加式补丁
- 不把“极端密集日志中的唯一单条精确命中”上升为当前阶段目标
