# Second Brain 后端答案引擎 · 精简产品定义

## 背景
- `F03` 已把默认结果页重构为 `Answer First, Evidence Second, Process Last`，但真实用户 case 暴露出两个 P0：长任务时后端收口不稳，以及默认引用混入大量低价值噪声。
- 当前问题已经不再是“能不能给出 citation”，而是“用户能不能快速完成一轮先拿答案、再判断能不能信、必要时核验原文的闭环”。
- 知识库数据并不是均质语料，而是混合了题目笔记、方法论总结、提交记录、失败代码、样板定义和对话残留。后端如果不先做价值分层，前端无论如何呈现都会继续被低价值证据污染。

## 目标与关键结果
- **总体目标**：把 OpenCode 后端从通用探索 agent 收束为可信回答优先的知识问答引擎。
- **KR1 首问可用率**：高频真实问题的首轮回答应稳定完整收口，不再把执行层内部状态直接暴露给用户。
- **KR2 默认引用质量**：默认主路径中的 `2-4` 条证据应能直接支撑回答主结论，并显著减少失败提交、样板代码、重复大文件切片等噪声。
- **KR3 边界清晰度**：对 `full-hit`、`partial-hit`、`no-hit` 三类问题，后端都能稳定输出一致的回答边界语义。
- **KR4 核验成本**：citation 默认应围绕命中片段组织核验，不再把整篇大文档直接推给用户。

## 范围
- 仅定义后端产品能力与契约，不定义前端默认布局、视觉层级和交互细节。
- 后端需要显式定义问题分型、回答状态、证据状态、失败状态，供前端直接消费。
- 重点解决默认主路径的可信度问题，而不是继续扩展 agent 的自由探索范围。

## 核心能力
- **回答边界**：先判断当前问题属于 `full-hit`、`partial-hit` 还是 `no-hit`，再决定是否继续探索或直接收口。
- **回答优先**：只要已有证据足以回答，就应尽快返回可消费回答，而不是继续为了“更完整”追加探索。
- **证据价值分层**：区分工作证据、候选证据、展示证据，禁止把中间推理噪声直接泄漏成默认引用。
- **默认证据发布**：默认只输出少量高价值、低验证成本、能直接支撑主结论的证据。题目笔记、方法论总结、解释性段落应优先于失败提交、样板代码和重复切片。
- **失败与降级收口**：当预算不足、命中不足或回答中断时，后端应输出产品化失败语义，例如无记录、记录不足、系统繁忙，而不是直接抛出 `maximum steps reached` 一类内部状态。
- **低成本核验契约**：citation 应帮助用户围绕命中片段完成核验，而不是把“可回跳”误做成“大文档地址定位”。

## 非目标
- 不追求把每一次工具读取和中间推理过程都暴露给用户。
- 不把“增加更多检索步骤”或“让 agent 更自由探索”视为目标。
- 不要求本轮先解决所有长尾内容质量问题，优先解决默认主路径的回答质量与信任建立问题。

## 验收标准
- 对真实高频问答 case，后端最终输出能稳定区分完整回答、部分回答和无记录回答。
- 默认展示证据能把主回答支撑起来，且不再频繁出现 `Runtime Error`、样板代码、重复大文件切片这类噪声主证据。
- 长任务或预算不足场景下，后端返回的是产品化失败语义或阶段性可用回答，而不是内部执行状态。
- citation 契约不仅可回溯，而且默认支持低成本核验。
- 在不新增复杂前端补偿逻辑的前提下，前端也能直接消费后端语义并形成一致体验。

## 后续拆分方向
1. **回答边界与收口契约**：统一 `full-hit / partial-hit / no-hit / failed` 的后端输出语义。
2. **默认证据质量与去重**：重建展示证据准入规则，优先高价值解释性片段，压制噪声切片。
3. **长任务阶段性回答与失败收口**：让后端在预算紧张或任务较长时，仍然优先输出可消费结果。
4. **低成本核验契约**：让 citation 默认围绕命中片段组织上下文，而不是把整篇大文档直接推给用户。
5. **后端评估与回归**：建立围绕真实用户问题的评测集，验证首问可用率、默认证据质量和失败收口质量。
